# A1: Runtime Episode ownership

The scientific workflow remains stopped and its persistent goal remains paused. This audit inspected source and final saved records only. No source/configuration changes, launches, model calls, simulator calls, replays, estimator fits or tests were performed. Only this report and its JSON companion were written.

Two verified binding defects concern assignment scope: a child changes the scientific task after recognizing that its assigned question is characterized, and non-root score assignment credits all received trajectory variants without an assignment-aware target. The real method_loop owns iteration and faithfully exposes those operations; replacing or bypassing it is not the correction.

Authority: BRIEF.md indexes the direct user requirements. Historical project documentation supplies implementation intent, not automatic approval. The concrete child request supplies its invocation scope. Template obligations are separated below from this binding's scalar score/continuation choices.

Final stopped state: **402 committed local units = 375 tool acquisitions + 27 child completions**, with **27 closed children** (19 simulation, 7 simparts, 1 math), all ended by yield_stop. Root has **20 committed turns**, credit **0.3574559702785158**, upper next-gain bound **0.05910150506675524**, cost **0.02**, stop **false**. There is no root summary. The attempt records CancelledError, 429 successful cached model responses, 324 fresh tool calls and 51 cached tool uses. Source: [STOPPED_STATE.json](STOPPED_STATE.json) and raw `run-scored-007/model-attempts/attempt-001/workflow-error.json`.

Current head is `29f5cda8dc3b615b0d0ffbdffbf43d22ef69a011`. All inspected current orbital Python files and all OpenChia method_loop Python files are byte-identical to frozen007 snapshots. Thus the current line references below describe the executed binding; no historical failure is being projected onto repaired code.

Runtime route: CLI `run/resume` → `run_scientific` → `DurableWorkflow.run_async` → actual `Episode.run_async` → `_Source`/`Policy.next` → `Leaf` or `StoredChildEpisodeUnit`. For a leaf: execute specified tool → project Evidence → current-scope controller advancement → append record → publish/save hook → obey stop. For a child: run/close child → build result → parent-owned numerical projection → typed report synthesis/admission → direct-parent report delivery → archive → one parent advancement. The optional generic GoalState commit path is not installed here.

Both reference designs were read. Nano's current core carries children directly as Episodes, exposes older compact updates, and has optional safety bounds; OpenChia uses the separate parent-owned ChildEpisodeUnit and mandatory reporting contract. Orbital imports OpenChia. Neither generic core mandates orbital's scalar formula, root/global shared credit, an incidence/hypervolume schema, or a new scientific acceptance gate.

Inspection covered complete source files listed in the JSON companion, including both method-loop implementations, communication docs, numeric composition/continuation, runtime consumers, storage and tool handlers. Saved records were parsed without executing project code. The dedicated A2/A3 reports own deeper statistical and communication analysis.
