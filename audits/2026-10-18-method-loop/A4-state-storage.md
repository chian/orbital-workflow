## State transitions and dependency boundaries

An action proposal is a cached model response. It is not a completed acquisition. `Policy.next` parses it and creates one `ToolAction` or `ChildAction` (`scientific.py:349–371`). The tool path then writes its request and immutable scientific objects (`tools.py:116–147`), writes a keyed tool response (`durable.py:106–123`), projects numerical Evidence (`scientific.py:231–252`), advances the local controller and creates a unit record (OpenChia `method_loop/episode.py:1248–1305,1421–1435`), and invokes `DurableWorkflow._record_unit`. That hook publishes viewer metadata/ownership before saving the immutable unit event (`durable.py:166–174`). There is no single transaction spanning those files.

A child first ends its own Episode and writes its closed trace (`episode.py:1126–1140`; `durable.py:176–179`), then builds its result, separately projects parent credit, synthesizes/admit its typed report, and delivers the update (`episode.py:1524–1573`). The orbital wrapper saves result/report and replaces the child trace with an archive reference (`archival.py:74–88`). Only then does the parent advance its controller for that one completed child acquisition. Consequently, a closed child trace can exist before parent communication has finished; `state: closed` in the episode manifest refers to that child's loop, not a committed parent turn. The saved result/report references must be read alongside it.

Resume starts fresh controllers and deterministically traverses the cached decisions/tools; it does not load saved credit totals and then add replayed deltas (`scientific.py:374–414`; `durable.py:126–174`). Existing immutable event equality checks prevent a different replay result silently replacing an earlier unit (`durable.py:67–79`). This is reconstruction, not a new scientific observation at every restored unit. Full cache replay was not performed during the audit.

The physical tool cache is shared inside one run; scientific best-score state is per Episode. `Workflow` creates `ReleasingContext` without a `GoalState` (`runtime.py:192–213`), and each scientific path creates its own `CreditController` (`scientific.py:153–157`). There is no designed mutable global scientific Goal registry here. The generic Goal preview/commit API exists in both method implementations, but orbital does not bind it. Principle 13's conditional shared-state refresh obligation therefore does not establish an ancestor-refresh defect in this binding. OpenChia's ordinary child-return boundary and nano's documented fan-up both treat one completed child as one parent unit; tool-cache sharing does not change that.

## 1. Verified defects

### A4-D1 — A crash between observation manifest and index publication leaves the viewer permanently missing a committed observation

- **Severity / principles / classification:** High; 8, 9, 19, 21; verified code-path defect, conditional occurrence. No 007 occurrence established. Uncertainty concerns whether a crash has happened, not the recovery branch's behavior.
- **1. Requirement and authority:** Explicit user invariant: committed work, recording and progress displays describe the same contribution; principles 8 and 19 require authoritative transitions and dependency-aware recovery. The requirement that a derived viewer index be reconstructible after a failed multi-file publication is an inferred engineering consequence, not an additional scientific gate.
- **2. Owner:** Orbital `EpisodeStore` owns the standard observation manifest/index/ownership projection; `DurableWorkflow` owns unit-event persistence. The generic core does not implement disk transactions.
- **3. Exact trigger:** The first publication of a saved simulation reaches `publish(manifest_path, ..., immutable=True)` and the process exits before publishing `episode-store/index/<ref>.json`. On later replay, the manifest already names a non-null `episode_id`.
- **4. Code path:** `storage.py:76–124`, specifically existing-manifest branch `90–97` versus first-publication `118–123`; `durable.py:166–174`; `runtime.py:160–169`; consumers `storage.py:171–184`, `viewer_timeline.py:26–50`, `visualization.py:56–72`. `publish` makes each individual JSON replacement atomic (`storage.py:14–27`) but does not make the pair atomic.
- **5. State effect:** On replay, `observe` appends the observation reference, sees the existing manifest, skips the only index-writing path, and still can publish ownership. The immutable unit event can subsequently be saved. The durable scientific objects and unit then exist while their derived index remains absent. Repeating the same replay does not repair it.
- **6. Communication effect:** The scientific Episode receives the cached Observation and normal projected Evidence. The generic viewer omits that simulation from `read_index`; ownership refers to an absent `by_id` entry and produces a pending-metadata warning. Thus responsible-Episode information and displayed progress can disagree indefinitely.
- **7. Credit effect:** The local controller can assign the actual saved score and ancestors can later receive it. The missing index does not directly erase or create credit. The defect is display/provenance divergence from otherwise committed accounting.
- **8. Controller effect:** Normal controller advancement and continuation can proceed after replay. This path does not itself add a second observation to the same reconstructed history.
- **9. Run evidence:** Run 007 has 227 index records and 305 ownership records; no ownership unit is missing its immutable unit event, no index's first owning unit lacks a unit event, and no `.pending` file is present. The triggering missing-index crash is not observed. `STOPPED_STATE.json` records user interruption, not a storage crash.
- **10. Smallest coherent correction, proposed only:** Treat index as a deterministic derived projection on every `observe` visit. Validate the existing manifest's identity, then ensure the index exists and agrees before publishing ownership/unit completion. Preserve existing first-owner metadata and acquisition order. Make the viewer's pending state recoverable from the manifest; do not fabricate a simulation or adjust its score.
- **11. Verification to perform later:** In an isolated storage experiment, terminate after manifest rename and before index rename, then exercise the ordinary resume path. Verify the original immutable objects/score and unit identity survive, the missing index is restored, ownership resolves, the viewer shows the acquisition, and no second local or ancestor yield observation is manufactured. No such experiment was run for this audit.

### A4-D2 — Immutable artifact creation can leave a poisoned final content-addressed path after interruption

- **Severity / principles / classification:** High; 8, 9, 18, 19; verified code-path defect, conditional occurrence. No partial-object occurrence established in 007.
- **1. Requirement and authority:** Explicit user requirements: authoritative durable state, useful retries that preserve valid partial work, and reuse only under correct dependency identity. Atomic publication of an object named by its complete bytes is an inferred implementation consequence of those requirements.
- **2. Owner:** Orbital `Artifacts._put` owns immutable object publication. `ToolDispatcher`, `CachedTools` and the standard episode store are consumers; OpenChia's generic method has no file writer here.
- **3. Exact trigger:** Process termination or a write error after `_put` creates the final `artifact_<full-payload-sha>.<suffix>` path but before the complete payload is written. A later request generates the same payload/hash, or tries to consume the saved reference.
- **4. Code path:** `artifacts.py:16–23` writes directly to the final pathname with `open('xb')` and `stream.write`; unlike `durable.py:67–79` and `storage.py:14–27`, it uses no staged file/flush/fsync/rename. Existing-path reuse is at `artifacts.py:19`; hash verification is at `33–40`. Producers include `simulation.py:152–170`, `tools.py:116–147,199–202`; consumers include `durable.py:109–119`, `tools.py:153–161` and `storage.py:78–100`.
- **5. State effect:** A truncated object occupies the permanent hash pathname. A retry of `_put` notices only existence and returns its identity without replacing or validating it. `payload` then correctly rejects the mismatched bytes. The same deterministic work can therefore remain unusable across repeated restarts even though it could be republished correctly from the same complete payload.
- **6. Communication effect:** Consumers receive `ValueError('Artifact bytes changed')` or downstream read failure; the exception propagates before a normal Observation/report or unit event for the affected action. Earlier completed unit files remain on disk. There is no structured acquisition repair path that turns this into useful new scientific information.
- **7. Credit effect:** The normal path reaches controller observation only after Evidence projection; a poisoned required object prevents that affected acquisition's credit. Existing committed credit is not intentionally invalidated, but reconstructing a prefix that needs the object may fail before its prior totals can be restored. No duplicate-gain claim follows from recomputation before commitment.
- **8. Controller effect:** An affected replay/run fails operationally rather than reaching the normal numerical continuation rule. Already-persisted controller steps remain evidence; no successful resume is established.
- **9. Run evidence:** No `.pending` files were found, but that alone cannot detect this defect because it writes to final names. No run-007 hash mismatch/error is established; this audit did not inject crashes or execute tool replay. The stopped error is `CancelledError`, with 402 already-committed units and the saved objects preserved.
- **10. Smallest coherent correction, proposed only:** Write each complete object to a unique staging file, flush/fsync it, then atomically publish the final hash pathname under the run's writer discipline. On an already-existing path, verify its hash before declaring reuse; distinguish a complete identical object from interrupted/corrupt publication. Retain evidence of corruption and republish only the exact known payload, with a clear recovery record. Apply the same rule to JSON and NPZ producers; do not rewrite scientific scores or silently accept changed bytes.
- **11. Verification to perform later:** In an isolated storage experiment, interrupt JSON and NPZ publication at several byte offsets and retry the identical payload. Confirm readers see either no final object or the complete hash-valid object; identical complete objects deduplicate; different bytes cannot replace the referenced identity; valid earlier acquisitions survive. Then verify normal resume still reconstructs each committed controller input once. Not run in this audit.

## 3. Mechanisms checked and working correctly

- **Actual loop and ownership:** Orbital imports and validates OpenChia's real method (`bootstrap.py:7–17`), using its actual `Episode` acquisition/controller/hook order. Nano's core and charter were read as design reference; its bound/old message APIs were not mistaken for live orbital behavior. The later user requirements supersede task-specific nano incidence/hypervolume policies.
- **Single-writer and immutable event agreement:** `RunLock` uses nonblocking `flock` for a run (`durable.py:82–96`), while keyed `save` compares old and recomputed JSON and refuses divergence (`67–79`). These are representation/concurrency boundaries, not scientific quality gates. Individual durable JSON writers stage/flush/fsync/rename. The unprotected object writer and cross-file gap are precisely D2 and D1, not evidence that every write mechanism is broken.
- **Cache scope and safe local reuse:** Tool cache keys include exact name/arguments (`durable.py:106–123`); scientific simulation arguments canonically include scenario gravity, forcing artifact, terms, interval, observation window and numerical settings (`scientific.py:189–208`; `simulation.py:31–110`). Input numeric spellings are normalized. Complete tool artifact bytes are hash checked on cache retrieval (`artifacts.py:33–47`). Configuration/persistence/code/library changes fail compatible resume before writer execution (`scientific.py:374–377`; `durable.py:42–64`). No global-new-science credit is inferred merely from a local cache hit.
- **Fresh controller reconstruction, without adding saved totals:** Resume traverses cached acquisition inputs through new path-owned controllers, and immutable events compare equal (`scientific.py:394–414`; `durable.py:139–174`). In 007 there was only one attempt and zero model replay; its 51 tool cache hits are within-run reuse, not proof of process-resume validation. Best-score credit is monotone in returned eligible scores (`credit.py:115–133`), so repeating the same score after it is already known locally produces zero improvement. A first local acquisition may legitimately improve that Episode while a parent that already knows it obtains zero new gain.
- **Closed trace release and archival provenance:** The orbital adapter empties closed recursive `unit_records`, retains a durable record/result pointer, strips raw child cycle logs from numerical projection, removes closed context updates/controllers, removes scientific per-path/controller/run-index state, drops cached conversation paths and retires provider workers (`archival.py:9–88`; `credit.py:27–34`; `scientific.py:177–183,280–308`; `durable.py:133–137`; `models.py:286–301`). The generic core's lack of a retirement API is handled by this actual binding. Successful retirement records in 007 support the reached lifecycle path; they do not prove an RSS ceiling.
- **Model/provider teardown:** `ModelConnection` owns one process per active Episode/role; release removes it, clears session/pending state, records exit and active count, and context exit releases remaining workers (`models.py:242–301`). The process-group TERM/wait/KILL path is explicit (`69–90`). All 55 saved retirements exit 0; `STOPPED_STATE.json` records no live owned provider groups after interruption.
- **Viewer storage consumes projections rather than recursive audit logs:** Catalog loading reads standard metadata/index/ownership/manifests (`visualization.py:35–88`; `viewer_timeline.py:6–61`). Numerical reads mmap selected arrays and cap displayed points (`storage.py:187–222`), while live server numeric payload caches are byte bounded (`viewer_server.py:34–78`). Offline export deliberately embeds selected saved packets and documents that embedded bytes still occupy memory (`visualization.py:98–143`); it is not evidence of a retained runtime child-trace leak.
- **Repeated publication on ordinary same-run replay:** Existing immutable unit/ownership/index records are equality checked and reused, not appended as fresh scientific events (`durable.py:67–79,166–174`; `storage.py:14–27,90–123`). Closed manifests can be republished while preserving existing result/report references (`storage.py:126–165`), so mtime-based viewer refresh can occur during reconstruction without manufacturing a new observation. Full process replay and interrupted publication were not tested; Q2 and D1 delimit those claims.
- **Removed-mechanism boundary checked in active consumers:** The live workflow binds `CreditController`/`ScalarScoreYieldEstimator` and archived child references; its score-yield input is completed acquisition marginal credit, not simulation duration, solver steps or a provider-worker count (`credit.py:146–191`; `score_yield.py:178–235`). Diagnostic bindings remain explicitly unscored alternatives (`runtime.py:216–253`), not a second scientific credit engine. This checked path does not establish repository-wide removal beyond the inspected storage/runtime/startup consumers.
